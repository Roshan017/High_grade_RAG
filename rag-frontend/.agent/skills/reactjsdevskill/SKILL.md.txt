Core Philosophy

Functionality first: Every component must work correctly before it looks good.
Composability: Build small, focused components that compose into larger features.
Performance by default: Avoid unnecessary re-renders, lazy load where it matters.
Accessibility always: Semantic HTML, ARIA roles, keyboard navigation — non-negotiable.
Real-world pragmatism: Use proven libraries. Don't reinvent wheels.

Component Architecture Rules
File & Folder Structure
src/
├── components/
│   ├── ui/          # Reusable primitives (Button, Input, Modal, etc.)
│   ├── layout/      # Shell, Sidebar, Navbar, Footer
│   └── features/    # Feature-scoped components (UserProfile, InvoiceTable)
├── pages/ (or app/ for Next.js)
├── hooks/           # Custom hooks — one hook per concern
├── stores/          # Zustand stores
├── lib/             # API clients, utils, constants
├── types/           # Shared TypeScript types/interfaces
└── assets/
Component Rules

One responsibility per component — if it's doing two things, split it.
Co-locate state — lift only when truly needed by a sibling.
Props over context for local component trees (<3 levels deep).
Context or Zustand for app-wide concerns (auth, theme, notifications).
Custom hooks for any logic that can be extracted (data fetching, form state, side effects).
Named exports for components, default export only for pages.


Code Quality Standards
TypeScript

Define interfaces for all props: interface ButtonProps { ... }
Avoid any — use unknown and narrow properly.
Type API responses explicitly; don't trust implicit inference from fetch.
Use discriminated unions for complex state: type Status = 'idle' | 'loading' | 'success' | 'error'

React Patterns

Prefer function declarations over arrow functions for components.
Use React.memo only when profiling confirms a re-render problem.
useCallback / useMemo — only for referential stability (callbacks passed to memoized children) or genuinely expensive computations.
Avoid prop drilling beyond 2 levels — reach for context or Zustand.
Handle all async states: loading skeleton, error state, empty state, success state.

UI/UX Standards
Design System

Define CSS variables for all colors, spacing, border-radius, typography in :root.
Support dark mode from day one using data-theme attribute or prefers-color-scheme.
Use a consistent spacing scale (4px base: 4, 8, 12, 16, 24, 32, 48, 64).
Typography hierarchy: display → heading → subheading → body → caption → label.

Component Patterns to Always Include

Loading states: Skeleton screens (not spinners) for content areas.
Error states: User-friendly messages with a retry action where possible.
Empty states: Helpful zero-state screens with a clear call to action.
Responsive: Mobile-first, test at 375px, 768px, 1280px breakpoints.
Keyboard navigation: Tab order, focus rings, Escape to close overlays.
Toast notifications: Use for async action feedback (save, delete, error).

Accessibility Checklist

Semantic HTML: <nav>, <main>, <section>, <button> (never <div onClick>)
All interactive elements are focusable and have visible focus rings.
Images have descriptive alt text.
Form inputs have associated <label> elements.
ARIA roles/attributes for dynamic content (modals, dropdowns, tabs).
Color contrast ratio ≥ 4.5:1 for normal text.

Auth Context Pattern
tsxinterface AuthContext {
  user: User | null;
  login: (credentials: LoginInput) => Promise<void>;
  logout: () => void;
  isAuthenticated: boolean;
}

const AuthContext = createContext<AuthContext | null>(null);

export const useAuth = () => {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used within AuthProvider');
  return ctx;
};
Protected Route
tsxfunction ProtectedRoute({ children }: { children: ReactNode }) {
  const { isAuthenticated } = useAuth();
  return isAuthenticated ? children : <Navigate to="/login" replace />;
}
Zustand Store
tsinterface AppStore {
  sidebarOpen: boolean;
  toggleSidebar: () => void;
}

export const useAppStore = create<AppStore>((set) => ({
  sidebarOpen: true,
  toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
}));

What To Build First (New App Workflow)
When starting a frontend from scratch, build in this order:

Project scaffold: Vite/Next.js setup, Tailwind config, folder structure, TypeScript config.
Design tokens: CSS variables for color palette, typography, spacing, shadows.
Layout shell: Top navbar, sidebar (if applicable), main content area, footer.
Routing: Define all routes upfront with placeholder page components.
Auth flow: Login page, auth context, protected routes.
API layer: Base client, interceptors, error handling.
Core features: Build page by page, component by component.
Polish: Loading/error/empty states, animations, responsiveness, accessibility.
